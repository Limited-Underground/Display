# OG-018I Cross-Repository Physical ACK Completion Composition

Date: 2026-08-09

Status: passed for two role-reversed close-bench cycles using production host
components from both repositories. This is not a long-lived on-device outbox,
authenticated physical key proof, direct target transport, or field result.

## Increment over OG-018H

OG-018H proved the normative alert and correlated ACK bytes survived both radio
legs. OG-018I additionally passed each returned physical ACK into a new
OpenGauge bench verifier built from the production components:

- `CriticalAlertOutbox` enqueued the exact sent `OGA0`, prepared it, verified
  byte equality, and committed local transport acceptance;
- `PeerAuthorizationRegistry` explicitly approved a trail-bridge peer with
  opaque key handle, authorization epoch, channel, and ACK permission;
- `CriticalAlertAckIngress` bound the exact consumer boot session and admitted
  the returned bytes only through authenticated transport metadata,
  authorization, codec, identity, observed-age, sequence replay, and exact
  event/condition/lifecycle outbox correlation;
- success required `outbox_completed=true`, one acknowledgement, and zero
  queued or in-flight entries.

The verifier reconstructs the exact outbox state on the host after the physical
round trip. It does not prove durable live state across the wait, process loss,
or device restart.
