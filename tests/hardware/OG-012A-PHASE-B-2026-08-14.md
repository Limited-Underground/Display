# OG-012A Round-Display Phase-B Evidence - 2026-08-14

Status: partial read-only Phase-B evidence only. This is not a flashing,
recovery, peripheral, compatibility, performance, or support result.

## Scope and preservation boundary

- Only the currently connected round display was in scope for this observation.
- The second display remained disconnected and untouched.
- The connected physical unit, its package, and a public-safe `OG-DISP-*` ID
  have not yet been associated. No exact received-board revision is claimed.
- No raw command log, COM name, device MAC, USB serial, private backup hash, or
  private backup path is retained in this public record.

## Read-only silicon, security, and flash observations

Installed `python -m esptool` version 5.3.1 was run without its RAM flasher stub
for the published metadata checks.

- `get-security-info` completed against an ESP32-S3 and reported Secure Boot
  disabled and flash encryption disabled.
- The redacted result did not expose a separate Secure Download value, so
  Secure Download Mode remains unreported and unknown in this public record.
  The separate `flash-id` command completed, but no broader or permanent
  security-state inference is accepted from that result.
- `flash-id` reported a detected flash size of 16 MB and public manufacturer
  and device codes `0x20` and `0x4018`. The codes are observations, not an exact
  board-revision or compatibility result.
- Exactly one Started Windows Port-class `303A:1001` interface reappeared after
  each metadata-command hard reset. This proves host USB re-enumeration only.
  The display was not visually observed after either reset, so return of the
  previously photographed powered demo is not accepted.

No flash, eFuse, security, or application data was erased or written.

## Private backup observation

- An initial 16 MiB read attempt using esptool's default RAM flasher stub reset
  the unit and attempted transient stub execution, then failed before flash
  transfer. The expected destination was checked and no partial backup remained;
  no erase, flash write, or eFuse operation was invoked.
- A 4 KiB full-flash probe through the ESP ROM loader using `--no-stub`
  completed before the full read was attempted.
- The full-flash read through the ESP ROM loader using `--no-stub` then
  completed in 1,694 seconds and produced exactly 16,777,216 bytes. The file was
  hashed and retained in an owner-private location outside Git. Its hash and
  path are intentionally not public.
- Exactly one Started `303A:1001` interface reappeared after the backup reset.
  No visual shipping-application confirmation was performed.

The private image has not been restore-tested. Its existence does not prove a
working restore path, the installed application's identity, or any peripheral.
