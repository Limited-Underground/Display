# OG-018J Physical Stale-Rejection Policy Composition

Date: 2026-08-09

Status: passed for two role-reversed close-bench cycles using production host
components from OpenTrail and OpenGauge. This is not persistent on-device state,
physical key authentication, a target transport, or a field result.

## Purpose and boundary

OG-018I proved the accepted branch completed an exact reconstructed outbox.
OG-018J proves a returned physical rejection does not become false delivery
success. OpenTrail evaluated the normative alert under a deliberately stale UTC
receive context and produced canonical rejected/stale through its real ingress
and responder. OpenGauge reconstructed the exact sent event as in-flight, then
processed the returned bytes through peer authorization, session binding,
replay/correlation ingress, and terminal rejection policy.

Success required `processed=true`, `outbox_completed=false`, zero
acknowledgements, stale rejection, no retry release, explicit terminal failure,
and zero queued/in-flight entries after terminal handling.

No secret or private device identifier is recorded.

## Remaining gates

- Exercise rate-limited/internal-error retry release over the physical path.
- Maintain real authorization/replay/outbox state across radio waits, restart,
  rebind, revoke, and power-loss cases.
- Bind protected keys and transport identities to selected target adapters.
- Replace the host/MeshCore adapter with direct authenticated on-device
  transport and run interference/range/field evidence.
